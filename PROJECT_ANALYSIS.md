# Project Analysis & Architecture Reference

This document serves as a living analysis report and reference guide for the **kintarowwwards** (SanjibPortfolio) project. 
It must be updated whenever significant architectural changes are made, and it should be used as a reference by developers (and AI assistants) to maintain consistency, quality, and standards for any new implementations.

## 1. Project Overview

**Kintarowwards** is a premium, interactive personal portfolio website inspired by Awwwards-winning designs. 
The core philosophy of the project prioritizes high-performance, fluid micro-interactions, responsive physics-based UI components, and clean code standards.

## 2. Technology Stack

*   **Core Framework**: Next.js 16 (App Router)
*   **UI Library**: React 19
*   **Styling**: Tailwind CSS v4
*   **Animations**: Framer Motion & `tw-animate-css`
*   **Scrolling**: Lenis (Smooth Scroll)
*   **Components & Icons**: Radix UI, Shadcn/UI, Lucide React
*   **Language & Typing**: TypeScript, Node.js v20
*   **Theming**: `next-themes` (Dark/Light mode support)

## 3. Project Architecture

The project follows the standard Next.js App Router architecture with specific structural rules.

### File & Folder Structure
*   **`app/`**: Contains all routing logic.
    *   **`app/[lang]/`**: The project utilizes dynamic route segments for built-in internationalization (i18n). Pages are rendered dynamically based on language codes (e.g., `en`, `tr`).
*   **`components/`**: Modularized UI elements grouped by responsibility:
    *   `effects/`: Visual effects, micro-animations, or particle engines.
    *   `layout/`: Structural layout components (Headers, Footers, Grids).
    *   `modals/`: Interactive dialogs and overlays.
    *   `sections/`: High-level page sections (Hero, About, Contact).
    *   `ui/`: Reusable, atomic UI components (often generated by Shadcn).
    *   `widgets/`: Complex, self-contained functional UI elements.
*   **`dictionaries/`**: Contains JSON translation files for i18n (`en.json`, `tr.json`).
*   **`lib/`**: Utility functions, generic helpers, and constants.
*   **`hooks/`**: Custom React hooks (e.g., `useScroll`, `useMousePosition`).
*   **`providers/`**: Global Context and State providers (Theme Provider, Lenis Provider, etc.).
*   **`contents/`**: Markdown/MDX or localized content files for dynamic data.
*   **`types/`**: Global TypeScript definitions and interfaces.

## 4. Development & Implementation Guidelines

When implementing new features or making changes, adhere to the following standards:

### A. Component Development
1.  **Server Components by Default**: Next.js 16 leverages React Server Components (RSC). Use Server Components as the default to keep bundles small.
2.  **Client Components**: Only use the `"use client"` directive when interactivity (Framer Motion, `useState`, `useEffect`, Event Listeners) is strictly necessary. Push client components down the tree as much as possible.
3.  **Atomic Design**: Utilize the `components/ui/` folder for base UI elements. Use Shadcn CLI or create manual wrappers with Tailwind.

### B. Styling & Theming
1.  **Tailwind CSS**: Use Tailwind utility classes for all styling. Rely on `clsx` and `tailwind-merge` (usually abstracted as a `cn` utility in `lib/utils.ts`) when merging conditional class names.
2.  **Theme Awareness**: Ensure any new UI element supports both light and dark modes (e.g., using Tailwind's `dark:` variant).
3.  **Aesthetics**: Follow the "Awwwards-quality" aesthetic. Use high-contrast typography, ample whitespace, and sleek color palettes. Avoid default browser styles.

### C. Animations & Physics
1.  **Framer Motion**: This is the primary driver for animations. Favor declarative layout animations and `useScroll` / `useTransform` hooks for scroll-linked animations.
2.  **Performance**: Use hardware-accelerated CSS properties (`transform`, `opacity`) in Framer Motion to prevent layout thrashing.
3.  **Smooth Scrolling**: Lenis handles scroll hijacking for a native feeling. Ensure any absolute/fixed elements do not break the Lenis scroll context.

### D. Internationalization (i18n)
1.  **No Hardcoded Strings**: Do not hardcode user-facing text in the components. 
2.  **Dictionaries**: Fetch strings from the `dictionaries/` JSON files based on the `[lang]` param provided in the route.

## 5. Review Checklist for New Implementations

Before finalizing any changes, ask yourself:
*   [ ] Does the feature work in both Light and Dark modes?
*   [ ] Is the component fully responsive (Mobile, Tablet, Desktop)?
*   [ ] Have all user-facing strings been abstracted to `dictionaries/`?
*   [ ] Is the animation smooth (60fps) without layout jank?
*   [ ] Is the component typed strictly using TypeScript interfaces?
*   [ ] Does this update require modifying this `PROJECT_ANALYSIS.md` file?
